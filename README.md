strctr — набор шаблонов, скриптов для проектирования интерфейсов и логики на стороне сервера (framework).

Синтаксис автора может и будет отличаться от общепринятых стандартов программирования среди сообществ разработчиков, этот проект создан для самовыражения и приобритения навыков программирования.

Работа с фреймворком на уровне http запросов отталкивается от понимания устройства каталогов в операционной системе, способов сопоставления с пространством имен и методов обращения к файлам средствами http. Архитектура скриптов отражает SOLID подход, но без строгого соблюдения всех принципов лежащих в основе проектирования данным способом. Разработка осуществляется для решения типичных задач веб-приложений, определить способы работы с: шаблонами, адресами, клиентами, данными, кешированием ...

Скрипт управляет состояниями объектов, для этого используются http методы: GET, POST, PUT, PATCH, DELETE, HEAD.

***Требования и цели в текущей версии

1. Все url обращения направлены на index.php для разбора uri на компоненты: расширение файла, имени файла, директории.

Настройками http сервера должнен быть предусмотрен запуск index.php для любых переданных адресов.

Nginx 
```
rewrite ^(.*)$ /index.php last;
```
Apache
```
RewriteEngine on
RewriteRule ^.*$ / [NC,L,QSA]
```

2. В url содержится информация для создания объекта с параметрами по умолчанию или настройками которые можно передать после вопросительного знака, для этого адрес сопоставляется с пространством имен.

В качестве примера вообразим что http сервер настроен для хоста `example.ru` показывать информацию из рабочей директории `/srv/http/example.ru`, допустим что в рабочей директории уже есть проект и к нему передан запрос `https://example.ru/path/app.html`.

Запрос будет разобран на следующие компоненты:

```
       расширение = html
      имя объекта = app
пространство имен = path/
```

Расширение позволяет определить формат вывода данных. Остальные компоненты uri используются для поиска вызываемого объекта, где `app` его имя, а `path/` пространство имен в которм объект может находиться. По сути переданый скриптам url будет преобразован из строки `https://example.ru/path/app.html` в вызов объекта `new \path\app()`.

3. Вместе с url может быть передана полезная нагрузка методами POST, PUT, PATCH для изменения состояния объекта

Вызванные объекты должны работать только с переданными и сохраненными данными. В отношении поступающей информации обязательно запускаются методы валидации данных, для уже хранимой информации используются методы кеширования.
